# Persistent Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a sidebar light/dark switch whose selection persists in IndexedDB and is reflected across dashboard components and charts in the compiled single-file artifact.

**Architecture:** A testable `RewstTheme` module owns theme validation, DOM application, preference-store access, palette reads, and chart refresh. The existing dashboard IndexedDB upgrade creates a separate `preferences` store, while the existing cache manager continues clearing only `cache_store`. CSS variables and explicit neutral-utility compatibility selectors make the root `data-theme` attribute the shared visual boundary.

**Tech Stack:** Vanilla JavaScript, IndexedDB, Node.js built-in test runner, Tailwind CDN utilities, Chart.js, CSS custom properties, the existing marker-based `build.js` pipeline.

## Global Constraints

- The output remains one deployable file at `dist/dashboard-spa-main-compiled.html`.
- The persistent theme owner is IndexedDB; do not add a localStorage theme fallback.
- Light mode is the default when no valid stored preference exists.
- Cache refresh and invalidation must never remove the theme preference.
- Do not add operating-system theme detection.
- Do not alter analytics APIs, cached analytics data formats, filtering, navigation, deployment configuration, or non-browser schemas.

  assert.equal(document.documentElement.dataset.theme, 'dark');

  assert.deepEqual(destroyed, [1, 2]);

- [ ] **Step 3: Implement the minimal UMD-style theme module**

Implement strict `light`/`dark` validation, root `dataset.theme` application, switch synchronization, persistence error reporting, and chart helpers. Export through `module.exports` under Node and `globalThis.RewstTheme` in the browser. Preference-store transactions must use the injected database and the dedicated object store:

```js
function createPreferenceStore({ getDatabase, storeName = 'preferences' }) {
  return {
    async load(key) {
      const db = await getDatabase();
      return requestResult(db.transaction(storeName, 'readonly').objectStore(storeName).get(key))
        .then(record => record?.value ?? null);
    },
    async save(key, value) {
      const db = await getDatabase();
      await requestResult(db.transaction(storeName, 'readwrite').objectStore(storeName).put({ key, value }));
    }
  };
}
```
